# fin-econ-data — Project Context for Claude

## What this is

A public static site at joemirza.com (repo `FuriousGeorge19/fin-econ-data`, local
`~/projects/fin-econ-data`) showing economic and financial data as interactive charts and
tables. Every page is generated by `scripts/build_site.py` from `series/*.json` (one
descriptor per dataset) and `pages/*.json`; charts are drawn by chart-type modules under
`site/js/charts/`. No backend, no JavaScript toolchain, no framework: Python stdlib plus
vanilla ES modules and Plotly from a CDN, hosted free on GitHub Pages.

The roadmap and its rationale live outside this repo, in
`~/Obsidian/Investing/Finance and Economic Data Website/`: `What I Want.md`, `Session Plan.md`
(one row per session with model, effort and mode — the row is authoritative), and the latest
`HANDOFF — <date>.md`. **Read the handoff first in a planning session.** This file describes
the build; the nested `CLAUDE.md` files below describe each area's rules.

## Data flow (the data-flow note that tests and scripts cite)

`scripts/fetch_<id>.py` → `data/<id>.json` → `scripts/build_site.py` copies it to
`site/data/` → GitHub Pages serves `gh-pages`. The daily workflow
(`.github/workflows/update-data.yml`, weekday evenings) seeds each `data/<id>.json` from the
live `gh-pages` copy, runs `scripts/fetch_all.py` (per-series failures are caught, the deploy
always runs, the job goes red afterwards), gates on `pytest -m "not staleness"`, builds, and
deploys. **It never commits fetched data back to `main`**: `main`'s `data/*.json` are test
fixtures that lag production, `gh-pages` is the deploy history, and `scripts/dev.sh --live`
pulls the live copies down when local work needs them.

## Run and test

```bash
scripts/dev.sh                 # build (with unpublished charts) + staleness warnings + serve
# open http://127.0.0.1:8899/  — use 127.0.0.1, not localhost; port 8888 belongs to another process
scripts/dev.sh --live          # first pull the published series' live data over http (not https)
FRED_API_KEY=… python3 scripts/fetch_fedfunds.py     # one series;  fetch_all.py for every series
python3 scripts/build_site.py                        # deploy build (published series only)
python3 scripts/catalog.py check                     # validate the catalogue + every descriptor reference
pip install -r requirements-test.txt && FRED_API_KEY=… pytest
pytest -m "not network"        # offline; network tests also skip themselves without the key
pytest -m "not staleness"      # the deploy gate
STALENESS_SOURCE=local pytest -m staleness   # freshness of data/ instead of the live site
```

`dev.sh` is the only way to see the five unpublished charts. The Shiller fetcher and its
tests need `pandas xlrd openpyxl`. Verify UI changes in the browser (Claude in Chrome) by
reading computed values, not only a screenshot, then commit and push; the workflow deploys.
`gh workflow run "Update Data"` deploys now; new pages can trail the run by ~3 minutes.

## Rules that prevent mistakes

- FRED's `"."` is missing, never zero (`fred_utils.fetch_series` drops it; `test_data_integrity.py`).
- Adding a series is file-additive: create files, edit no shared file, no workflow, HTML or
  nav edit (`openspec/specs/site-build/spec.md`).
- A fetcher never reads a sibling's `data/*.json` — fetch order is not guaranteed (`scripts/CLAUDE.md`).
- Derived series compute in Python at fetch time, never in JS.
- Under `site/js`: no hex/rgb colour literal; `margin`/`rangeslider`/`height`/`getElementById`
  only in `lib/plotly-layout.js` and `lib/card.js`; no module-level state in a chart type
  (`test_build_site.py` greps the tree).
- Descriptor prose reaches the site only at fetch time; rerun the fetcher to see an edit.
- The five ids in `tests/test_build_site.py`'s `LICENCE_RESTRICTED` stay `publish: false`
  until a terms decision is recorded in the Session Plan (below).
- No hand-maintained counts or inventories in any doc: `ls series/`, `ls catalog/sources/`
  and `python3 scripts/catalog.py report` are the inventory. Counts here have drifted before.
- Never add `Co-Authored-By` or similar trailers to commits.
- Every generated page carries the FRED API notice in its footer (`FRED_API_NOTICE`, tested).
- Recession shading on a time-series chart (`recessions: true`) unless there is a reason
  not to; never upsample monthly data; make gaps visible; no dual y-axes
  (`series/CLAUDE.md` has the full list).

## Adding things

**A series that fits an existing chart type** (`timeseries`, `curve`, `tenors`) — the common
case, four new files and no edits:

0. Catalogue entry: a public-domain FRED series needs a `datasets[]` entry in
   `catalog/sources/fred.json`; a new rights holder needs its own file. `catalog.py check`
   until silent. Skipping this fails the fetch with an unresolved source.
1. `series/<id>.json` — copy `series/fedfunds.json`; `sources[]` are catalogue references
   `{slug, dataset?}`; `presentation` picks sections, order, chart type and options.
2. `scripts/fetch_<id>.py` (or point the descriptor's `fetcher` key at an existing script).
   Run it once locally so `data/<id>.json` exists.
3. `tests/test_<id>.py`: structural invariants plus a live cross-check.
4. `python3 scripts/build_site.py` — the page, its section entries and the nav follow.

Then, if wanted, curate it onto `/` in `pages/home.json` — a separate, deliberate edit.

- **A view** (a page over another series' data): `presentation.data: "<id>"`, no fetcher, no
  data file (`series/CLAUDE.md`).
- **A new chart type**: one new `site/js/charts/<type>.js` following the render contract in
  `openspec/specs/chart-components/spec.md` (`site/js/CLAUDE.md`).
- **A new data source**: one file under `catalog/sources/`, copying `shiller.json` (`catalog/CLAUDE.md`).
- **A chart too wide for half width**: `presentation.size: "full"`.
- **Keeping a series off the public site**: `presentation.publish: false` — for terms, not for
  work in progress.

## Unpublished series

`sp500_pe`, `sp500_cape`, `sp500_dividend_yield`, `sp500_earnings_yield` and
`equity_risk_premium` build locally only. S&P Dow Jones Indices refused free permission to
display index values or P/E values on 2026-09-15, and Shiller's side deferred to S&P on
2026-09-17; everything derived from S&P price, dividends or earnings inherits that. The per-id
reason is in `LICENCE_RESTRICTED` (`tests/test_build_site.py`), the terms record in
`catalog/CLAUDE.md`, the history in `CHANGELOG.md`. Before publishing anything new, its
sources must resolve `verified` (`python3 scripts/catalog.py report`).

## Pointers

- `CHANGELOG.md` — per-session record, newest first; also holds the pre-split Current State,
  Key Files and Licence Notes verbatim.
- `ARCHITECTURE.md` — evolution triggers (when a refactor becomes due), the decision log,
  the original chart roadmap.
- `HOW-IT-WORKS.md` — end-to-end narrative for a human reader, DNS/hosting/secrets detail,
  troubleshooting.
- `openspec/specs/<capability>/spec.md` — the authoritative statement of each rule; changes
  go through an OpenSpec change (`/opsx:*` skills).
- `catalog/README.md` — the catalogue's rules and field table.
- The Obsidian folder above — goals, Session Plan, handoffs, the S10 chart proposals.

## Where a new fact goes (end-of-session routing)

| What happened | Goes to | Never to |
|---|---|---|
| A rule an agent could break in one edit | the `CLAUDE.md` nearest the files it protects; here only if it spans directories; name the enforcing test | a paragraph here |
| What a session built | `CHANGELOG.md`, one entry of ≤ ~15 lines, plus the Session Plan row and a handoff | a "Current State" list here |
| A decision with rationale | `ARCHITECTURE.md`'s decision log or the OpenSpec change's `design.md`; extract a one-line rule if it constrains future edits | prose here |
| A licence fact | `catalog/sources/<slug>.json` + `catalog/research-log.md`; `LICENCE_RESTRICTED` if publishability changes; `catalog/CLAUDE.md`'s table | here |
| A gotcha (port, CDN lag, a flaky test) | `HOW-IT-WORKS.md` Troubleshooting; the one-line imperative here | a narrative here |
| A new series, source or chart type | nothing in docs — `ls` and `catalog.py report` are the inventory | any list |
| A directory that acquires three or more rules of its own | its own `CLAUDE.md`, added to the Map | here |

`tests/test_docs.py` fails if this file passes 200 lines or regrows dated bullets. Checked
2026-09-18: a subagent that reads a file under `series/` does receive `series/CLAUDE.md`;
whether it starts with this root file depends on the agent type (a general-purpose agent had
the copy from session start, an Explore agent had none) — so a workflow or subagent prompt
should still say "read `CLAUDE.md` first".

## Ops
